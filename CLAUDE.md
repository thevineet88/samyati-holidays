# CLAUDE.md

## What this is

The public-facing marketing website for Samyati Holidays, a Mumbai and Pune
based group tour operator. A **static brochure site** — 28 fixed-departure
package pages, a listing page, a home page, and supporting pages. Deployed on
Netlify at samyatiholidays.com.

**This site does not take bookings or payments.** Its only job is to show trip
details and push every visitor toward WhatsApp. Every "Book on WhatsApp" button
opens a `wa.me` link to +91 90760 68549. Every contact form posts to Formspree.
No exceptions.

## Business context

Samyati runs fully organized group tours from Mumbai and Pune: spiritual
yatras (Kedarnath-Badrinath), beach trips (Gokarna-Murudeshwar), high-altitude
adventure (Sikkim-Darjeeling), Himalayan treks, Char Dham circuits, Ladies
Special and Parents Special tours. Tagline is "Feeling FamilyVali."

## Architecture

```
packages/*.json        ← Package data (one JSON per package)
build.js               ← SSG: renders JSON → template.html → dist/<slug>.html
template.html          ← Mustache-style {{VARIABLE}} template for package pages
_partials/              ← Header, footer, lead-popup partials injected by build.js
css/                    ← input.css (Tailwind source) → style.css (compiled output)
dist/                  ← Build output (git-ignored, regenerated by build.js)
js/packages-data.js    ← Auto-generated mirror of all packages for browser-side use
js/main.js             ← Accordion, nav, dynamic card rendering, form submission
js/preloader.js        ← Splash screen animation
index.html             ← Home page (static, hand-written)
packages.html          ← Package listing page (renders cards from packages-data.js)
package-detail.html    ← Dynamic detail view (slug-based, reads packages-data.js)
about.html / contact.html — Static pages
```

### Build pipeline

1. Edit or add a JSON in `packages/*.json`
2. Run `node build.js`
3. Output: `dist/<slug>.html` — one self-contained HTML per package
4. `js/packages-data.js` is also regenerated (mirror for `packages.html` and
   `package-detail.html`)
5. Header and footer partials from `_partials/` are injected at build time

**Every HTML file in `dist/` is fully self-contained.** The template embeds
the header, footer, hero, itinerary, inclusions/exclusions, payment schedule,
refund policy, and enquiry form — no external dependencies beyond the CSS CDN.

### Data model

Each `packages/<slug>.json` carries:

- **Identity**: slug, title, subtitle, overview
- **Display**: hero image, category tags, transport mode
- **Summary**: dates, duration, price (INR per person), price note, last booking date
- **Content**: highlights array, advisory text
- **Travel**: departure point, transport mode/name, return point
- **Itinerary**: ordered day-by-day array (day number, title, description, meals)
- **Inclusions / Exclusions**: two separate string arrays
- **Payment schedule**: array of { name, amount, dueBy }
- **Cancellation policy**: array of { deadline, deduction }
- **Notes**: operational disclaimers array

Categories: Spiritual, Beach, Adventure, Nature & Hills, Ladies Special,
Parents Special.

## Page structure

### Package detail pages (built via template.html)

Every package page is a self-contained SEO landing page. Structure:

1. Fixed header with nav + logo
2. Hero with destination image, breadcrumb, category badges, price/dates
3. Package overview (if subtitle + overview exist)
4. Trip highlights (grid of bullet cards)
5. Travel details (departure, mode, return — 3 info cards)
6. Detailed itinerary (accordion, day by day with meal tags)
7. Inclusions and exclusions (two columns)
8. Payment schedule (table)
9. Refund & cancellation policy (table + standing rule)
10. Sidebar: enquiry form + summary box (dates, duration, price, last booking)
11. Footer (static, same across all pages)

### packages.html

Renders all 28 package cards dynamically from `packages-data.js`. Category
filter tabs. "Coming Soon" badge for packages flagged in data. Sorted by price.

### package-detail.html

Single-page router: reads URL slug, looks up the package in
`js/packages-data.js`, renders the full detail view with the same sidebar
enquiry form.

### about.html

Static page with company info, team members (with local headshots), and company story.

## Conventions

- **Build required for changes.** Run `node build.js` after editing any JSON in
  `packages/`, partials in `_partials/`, or CSS in `css/input.css`. The build
  regenerates `dist/`, `js/packages-data.js`, and root-level HTML pages.
- **Packages are data-first.** The canonical source is `packages/<slug>.json`.
  HTML is generated output. When JSON changes, run `node build.js`.
- **No secrets in code.** Formspree endpoint is public (it's a form ID, not a
  key). No API keys, tokens, or credentials anywhere in the repo.
- **WhatsApp is the booking channel.** Every CTA goes to `wa.me/919076068549`.
  Pre-filled messages are set per context (general enquiry, specific package,
  booking interest).
- **No random images.** Every hero image is a curated Unsplash URL matching the
  destination. Do not replace with placeholder or mismatched images.
- **Responsive images** in `assets/images/` use `srcset` with 600w / 800w / 1200w
  variants for adaptive loading.

## What not to do

- Do not introduce a framework, bundler, or build system beyond `build.js`.
- Do not take bookings or process payments on this site.
- Do not add packages without a corresponding `packages/<slug>.json`.
- Do not re-introduce JS-rendered components (header, footer). They are injected
  from `_partials/` at build time via `build.js`, not rendered by the browser.
- Do not use placeholder images or image URLs that don't match the destination.
